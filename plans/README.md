## Findings considered and rejected (Aug 29 batch)

- **Expose DataTable cell values to the remote UI tree**: ~~deferred~~
  **RESOLVED (Aug 29)** — shipped as a pull-based `readRows` remote-ui action on
  `DataTable`, not as pushed metadata. The two constraints that caused the
  deferral both dissolved on inspection:
  - `renderCell` already returns `DataTableCell { text: string }` and
    `renderSectionHeader` already returns `{ text: string }`, so every rendered
    cell and group header is *already a plain string*. No serialization layer was
    needed.
  - Remote-ui actions can return values (`RemoteUiAction = (input?: unknown) =>
    unknown | Promise<unknown>`; `invoke` returns `await handler(input)` and
    `controller.ts` surfaces it via `getAfterMutationSummary({ result })`), so the
    read is a **pull**. It costs nothing until an agent calls it and adds **zero
    bytes** to the pushed snapshot — which is why the payload-size objection no
    longer applies.

  Plan 006's memoization is untouched: `readRows` reads `livePropsRef.current`,
  which sits outside the memo dependencies, and the pre-existing test asserting
  the metadata contains **no** `rows` key still passes. Reads are bounded
  (`start`/`limit`, default 50, hard cap 500) and return
  `{ index, key, selected, sectionHeader?, cells }`. This unblocks value-accuracy
  QA: plan 071 gained **Step 6b `group-header-equals-first-child`**, which targets
  the exact `69%`-above-`51%` bug class that motivated this entry.
- **HTTP record/replay cassettes for deterministic CI**: deferred. No recording
  layer exists anywhere in the repo; `mock.module()` is the only mechanism and it
  is process-wide and permanent in Bun (the direct cause of a large share of the
  91-failure baseline). Cassettes would let live-data invariants move from the
  scheduled canary into the PR gate. Out of scope for 071 by operator decision;
  revisit once 071 has proven the invariant layer is worth deepening.
- **Consolidating `verify.yml` and `pr-checks.yml`**: still rejected — see TECH-03
  below. Plan 072 makes the code pass both gates rather than merging them.
- **CONTRACT-C-01 (Jina AI reader reports to an unregistered connection source)**:
  **false positive, do not re-audit.** An audit reported that
  `src/plugins/builtin/shared/jina-reader.tsx:20` reports traffic under
  `"jina-ai"` with no matching `registerConnectionSource()`. It is in fact
  registered at `src/plugins/builtin/news/wire/index.tsx:242-247` with a dispose
  handle. The audit searched only the `connections/` directory; registration
  correctly happens in the owning plugin's `setup()`. The connection inventory is
  clean.
- **TEST-01 (`src/test-support/setup.ts` overwrites rAF without restore)**: not a

  `cancelAnimationFrame` in `beforeEach` without preserving the previous values

- **PERFORMANCE-01 (Kalshi poll has no in-flight guard)**: folded into plan 066

## Findings considered and rejected

- **SECURITY-04 (AI remote-control no approval gate)**: not planned because the
  risk is prompt-injection-driven, not a direct code vulnerability. The system
  prompt already includes injection defenses. An approval gate is a product
  decision that changes the AI workflow UX, not a straightforward code fix.
  Worth revisiting if AI agent usage grows.
- **CORRECTNESS-02 (non-null assertions on potentially empty arrays)**: not
  worth a standalone plan. The guards exist and are correct for current code
  paths. The `!` assertions are fragile but not currently broken. Covered by
  enabling `noUncheckedIndexedAccess` (already enabled in tsconfig) and code
  review diligence.
- **CORRECTNESS-05 (IBKR double-Enter order submission)**: not planned because
  the two-Enter preview-then-submit flow is intentional UX for fast trading.
  Adding a confirmation dialog is a product decision, not a bug fix. The
  preview step serves as the confirmation.
- **PERF-03 (Bollinger band re-slices window)**: not worth a standalone plan.
  Default period (20) keeps this bounded. Only impacts users with very long

  rolling variance.
